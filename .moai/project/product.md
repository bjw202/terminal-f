# terminal-f — 제품 개요

> 이 문서는 **무엇을, 누구를 위해, 왜** 만드는지를 다룬다. 구현 구조는
> `structure.md`, 기술 스택과 빌드/테스트 절차는 `tech.md`를 참고할 것.

## 1. 제품 정체성

terminal-f는 **Windows 전용 네이티브 터미널 에뮬레이터**다. Tauri 2 기반으로,
Rust 백엔드(portable-pty → ConPTY)가 모든 상태를 소유하고 TypeScript +
xterm.js 프론트엔드(프레임워크 없는 vanilla, imperative DOM)는 그리기만
한다. 화면을 여러 칸으로 나누는 **분할 페인**, 프로젝트별 작업 책상을 여러
개 두는 **워크스페이스**, 그리고 AI CLI 도구(Claude Code, Codex 등)를
동시에 여러 개 띄워 쓰는 워크플로를 위해 설계됐다.

버전 `0.1.1` (`productName: terminal-f`, `identifier: com.terminalf.app`),
런타임 상태는 `%APPDATA%\com.terminalf.app\`에 저장된다.

## 2. 대상 사용자

**팀/사내 공유**를 전제로 한다. 개인 해커용 도구나 공개 OSS 배포물이
아니라, 같은 팀이 함께 쓰는 터미널 환경으로 자리매김한다. 이것이 의미하는
바:

- **워크스페이스 = 팀 구성원이 공유하는 작업 단위 개념**이다. 온보딩 시
  새 팀원은 워크스페이스/페인/템플릿 개념을 먼저 이해해야 한다.
- **템플릿(레시피)과 저장소 프로필**(`<repo>/.terminal-f/profile.json`)이
  공유의 핵심 통로다. 한 사람이 워크스페이스 셋업(칸 나누기 + cwd +
  시작 커맨드)을 템플릿으로 저장하면, 같은 저장소를 쓰는 다른 팀원이
  그대로 재현할 수 있다(ADR-009).
- **신뢰 게이트**(`trustedRepos`)는 팀/사내 공유 시나리오에서 특히
  중요하다 — 낯선 저장소를 클론했을 때 자동 실행 커맨드가 몰래 돌지
  않도록 사용자 확인을 강제한다.
- **자동화 규칙**(git-diff 감시, 타이머)과 **컨트롤 API**(named pipe,
  브로커 연동)는 팀이 공유 규약으로 자동화 워크플로를 구축할 수 있게
  하는 확장점이다.

## 3. 해결하는 문제

1. **AI CLI 세션을 여러 개 동시에 운용하기 어렵다.** 일반 터미널은 탭 하나
   = 세션 하나이며, 탭을 닫으면(또는 다른 작업으로 화면을 전환하면) 진행
   중인 작업이 끊긴다.
2. **Windows에서 스크린샷을 AI CLI에 붙여넣을 방법이 없다.** Ctrl+V는
   클립보드의 텍스트만 전달하고, 이미지가 있으면 아무 일도 일어나지
   않는다.
3. **화면 갱신이 활발한 프로그램(AI CLI streaming 출력) 위에서 한글을
   입력하면 조합 중인 글자가 깨진다.** IME 조합과 화면 재렌더링이
   충돌하기 때문이다.
4. **자동화(브로커 프로그램)가 터미널에 안전하게 개입할 표준 통로가
   없다.** 임의의 프로그램이 셸에 직접 타이핑하는 것은 위험한 작업이며,
   안전장치 없이 노출하면 사고 위험이 크다.

## 4. 핵심 가치 3축

1. **백엔드 소유 상태(Backend-owned state)** — PTY 세션, 페인 트리,
   워크스페이스, 자동화 규칙, 주입 게이트가 전부 Rust에 있다. WebView는
   그리기만 한다. 그래서 워크스페이스를 전환해도 실행 중인 작업이 멈추지
   않는다(ADR-001, ADR-002).
2. **터미널로 들어가는 프로그래밍 가능하고 안전장치를 갖춘 쓰기 경로** —
   프롬프트 주입 + 자동화 규칙 엔진 + named-pipe 컨트롤 API. 일반
   터미널 에뮬레이터에는 이런 대응물이 없다. 모든 자동 주입은 킬 스위치 →
   대상 결정 → 페인별 허용 목록 → 유휴 게이트 → 브래킷 붙여넣기 → 감사
   로그의 단일 경로(`do_inject`)를 통과한다(ADR-006~008).
3. **Windows 고유의 통증점 해결** — 클립보드 이미지 붙여넣기를 파일
   경로 전달로 우회(ADR-010), 셸 통합(OSC 9;9/7)을 통한 라이브 cwd
   추적(ADR-011), 스트리밍 출력 중 한글 조합 안정화.

주된 사용 시나리오는 여러 개의 AI CLI 에이전트(Claude Code, Codex)를
나란히 띄워 작업하는 것, 그리고 외부 브로커/자동화 작성자를 위한
확장점 제공이다.

## 5. 구현된 기능 요약

| 영역 | 기능 |
|---|---|
| 워크스페이스 | 생성/이름변경/삭제/전환/순서변경, 색 라벨, 활동 표시 점, `Ctrl+1~8`, 소프트 캡 8 / 하드 캡 16, keep-alive(ADR-002) |
| 페인 분할 | 이진 트리, `Ctrl+Shift+D`/`Ctrl+Shift+-`/`Ctrl+Shift+W`/`Ctrl+Shift+Z`, ratio ∈ [0.1, 0.9] 클램프 |
| 명령 팔레트 | `Ctrl+Shift+P` |
| 템플릿 & 저장소 프로필 | `<repo>/.terminal-f/profile.json`, `trustedRepos` 신뢰 게이트, `${repo}` 변수 (ADR-009) |
| 주입 안전 게이트 | 킬 스위치 → 대상 결정 → 페인별 `allowInjection`(기본 false) → 1.5초 유휴 게이트 → 브래킷 붙여넣기 → JSONL 감사 로그; 모든 경로가 `commands.rs::do_inject`로 수렴(ADR-006) |
| 자동화 규칙 | `gitDiff` / `timer` 소스, 2초 폴링, 기본 확인(confirm-by-default) 제안(ADR-007) |
| 컨트롤 API | Windows named pipe, `control-api.json` 토큰 인증, JSON-RPC; 관찰(observe)은 페인별 `allowObserve`(기본 false)로 게이트(ADR-008) |
| 셸 통합 라이브 cwd | OSC 9;9 / OSC 7 파싱, split 시 라이브 cwd 상속(ADR-011) |
| 이미지 붙여넣기 + 파일 드롭 | 클립보드 이미지 → PNG 저장 → 경로 붙여넣기; 탐색기 드래그앤드롭(ADR-010) |
| 복사 UX | 스마트 Ctrl+C/Ctrl+Shift+C/우클릭/copy-on-select/OSC 52 write-only |
| 멀티라인 입력 | Ctrl+Enter 청크(IME 순서 안전) |
| IME/한글 안정화 | 조합 중 출력 버퍼링 + 에코 통과창 + 워치독 |
| URL 열기 보안 | http/https 스킴 화이트리스트 + Ctrl/Cmd 클릭 게이트, `tauri-plugin-opener` 경유(ADR-012) |
| 테마/폰트 | 다중 테마(Campbell 포함) + 글자 크기 조절 |

## 6. 범위 / 비범위

**현재 방향: 현재 범위 유지 + 사용성 다듬기.** 이는 결정 사항이며,
향후 SPEC을 심사할 때의 기준으로 인용할 수 있다.

### 범위 (Scope)

- **UX 다듬기**: 기존 기능(복사, 멀티라인, 라이브 cwd, 테마, IME 등)의
  체감 품질을 개선하는 작업.
- **안정성**: 회귀 방지, 실기기 검증이 필요한 함정(IME/클립보드/셸 통합)의
  견고화.
- **설정 영속화**: `config.json` 스키마 마이그레이션 절차를 따르는 점진적
  필드 추가 (예: 진행 중인 [SPEC-WORKSPACE-ROOT-001](../specs/SPEC-WORKSPACE-ROOT-001/spec.md) —
  워크스페이스 시작 폴더 + 네이티브 폴더 선택 대화상자. `docs/DEVELOPMENT.md`
  §10 로드맵의 "템플릿 UX: 폴더 피커 다이얼로그" 항목의 첫 조각에 해당한다).

### 비범위 (Non-goals)

- **대규모 신규 서브시스템 도입.** 예: 새로운 통신 프로토콜, 새로운 렌더링
  엔진, 플러그인 시스템, 크로스 플랫폼(macOS/Linux) 확장, 원격 세션.
- **완전히 새로운 사용자 플로 개발.** 기존 워크스페이스/페인/템플릿/자동화
  모델을 대체하는 새 개념 도입은 이 범위 밖이다. 로드맵의 M1(브로드캐스트
  입력, 세션 재연결 고도화)과 컨트롤 API 확장(capability scope, rate
  limit, 이벤트 push)은 "새 서브시스템"에 가깝고, 현재 방향(다듬기)과는
  별개로 별도 결정 없이는 착수하지 않는다.

이 범위/비범위는 새 SPEC이 들어올 때 "지금 방향에 맞는가"를 가르는
1차 기준으로 쓰인다.

## 7. 현재 상태

- **버전 0.1.1**, git 커밋 6개, 최신 커밋
  `f8157b3 terminal-f 0.1.1: IME echo pass-through (Korean typing latency/overlap fix)`.
- **ADR 12건** 채택(ADR-001~012), 모두 배경 → 결정 → 트레이드오프 → 테스트
  구조로 기록되어 있고 실패 후 재설계 사례(ADR-010)도 남아 있다.
- **로컬 검증 체계**: `cargo test`(98개 단위/통합 테스트) → `npm run build`
  (타입체크 + 번들) → 인앱 autotest(32개 검사, `ok: true`)의 3단계 순서를
  전부 통과해야 "완료"로 선언한다. GitHub Actions에는 빌드/테스트 워크플로가
  없다 — CI는 로컬 검증에 전적으로 의존한다(자세한 내용은 `tech.md` 참고).
- 진행 중: [SPEC-WORKSPACE-ROOT-001](../specs/SPEC-WORKSPACE-ROOT-001/spec.md)
  (워크스페이스 시작 폴더, `status: draft`, `phase: v0.1.2 target`).

## 8. 남은 로드맵

`docs/DEVELOPMENT.md` §10 기준:

- **UX 다듬기 4건** — 기획 완료, 문서상 "미구현"으로 표기되어 있으나
  README/모듈 지도상으로는 복사·멀티라인·라이브 cwd·Campbell 테마가 이미
  구현·릴리스된 상태(문서 갱신 지연 가능성, 미확인). 상세 계획은
  `docs/PLAN-UX-polish.md`.
- **M1** — 여러 페인에 동시 입력 브로드캐스트, 세션 재연결 고도화.
- **템플릿 UX** — 네이티브 폴더 피커 대화상자(진행 중, 위 SPEC 참고),
  템플릿 편집 UI, `${repo}` 자동 일반화.
- **컨트롤 API** — 브로커별 capability 스코프, rate limit, 폴링 대신
  이벤트 push.
- **팔레트** — 카테고리 구분, 최근 사용 우선 정렬.

이 로드맵 항목들은 "대규모 신규 서브시스템"에 해당하는 것과 "다듬기"에
해당하는 것이 섞여 있다 — §6 범위/비범위 판단 시 항목별로 재확인할 것.
